# 0804_1_ 主板应用说明

## 功能概览

该应用运行在 Zynq-7000 的 Cortex-A9 裸机环境，负责 AD7606 采集、流量算法、RS485/Modbus 屏幕通信、脉冲输出以及增益调理板控制。

## 增益切档链路

屏幕将切档按钮写入 Modbus 保持寄存器 4WUB0141～4WUB0145（程序寄存器 140～144）。主循环每 200 ms 轮询一次这些寄存器，收到 1～4 档命令后执行：

1. 通过 `can_send_gain_level()` 从 MIO9 发送一帧模拟 CAN GPIO 波形。
2. 清除屏幕的切档命令寄存器，避免重复执行。
3. 发送函数返回成功后，将当前档位写入状态寄存器 4WUB0140（程序寄存器 139）。

启动时默认档位为 4，`gain_init()` 会先初始化 MIO9，然后发送一次第 4 档命令，再更新屏幕状态。

相关代码：

- `can.c/.h`：模拟 CAN GPIO 发送模块。
- `main.c:gain_init()`：启动初始化和默认档位发送。
- `main.c:gain_apply_stage()`：屏幕命令到增益帧的转换。
- `rs485_modbus.c/.h`：屏幕 Modbus 寄存器读写。

## 模拟 CAN GPIO 协议

当前实现不是 ISO 11898 标准 CAN 控制器帧，而是参考增益小板测试程序的单线 GPIO 协议：

- 主板发送脚：PS MIO9。
- 增益小板接收脚：STM32 PA11。
- 空闲电平：高电平。
- 单 bit 时间：50 us。
- 每个字节：低位在前（LSB first）。
- 帧内容：`A5 20 A3 level ~level CRC8`。
- `CRC8`：多项式 `0x07`，初值 `0x00`，计算前 5 个字节。
- 帧前导：高 4 bit、低 3 bit、高 2 bit。
- 帧结束：保持高电平 4 bit。

增益小板必须使用对应的 `SIM_CAN_GPIO_RX_TEST` 接收实现，并确保 MIO9 与 PA11 的信号链路和地线连接正确。该协议没有标准 CAN 的仲裁、位填充、ACK 或错误重传机制。

## 当前限制

- 支持实际硬件档位为 1～4。
- 屏幕的“自适应增益”命令映射为档位 5，但增益 GPIO 接收端只接受 1～4；自适应增益策略尚未实现。
- 模拟发送函数的“成功”表示 GPIO 波形已经输出，不代表接收端已确认切档。
- 修改 `can.c` 的 MIO、时序或帧格式时，必须同步修改 STM32 接收端。

## K/B 参数

启动时 `calibration_init()` 先设置编译默认值 K=0.8、B=0。RS485 初始化完成后，程序会读取屏幕状态寄存器里的 K/B；如果屏幕给出的值有效，就用屏幕值覆盖运行参数，否则继续使用编译默认值。

当屏幕手动输入 K/B 并触发“应用”时，程序会直接用新输入值替换当前运行 K/B，并把状态回写到屏幕。当前版本不再把 K/B 写入板载 Flash，因此断电重启后不会从 Flash 恢复上一次输入值。

## 构建

在 Vitis 2022.2 中刷新 `src` 目录后构建 `0804_1_` 应用。命令行构建时，`Debug/src/subdir.mk` 中必须包含 `can.c`。构建产物为 `Debug/0804_1_.elf`。
